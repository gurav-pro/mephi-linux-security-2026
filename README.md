## Раздел 1. Создание пользователя
 
**Задание:** создать обычного пользователя user1 с UID 1234, входит в группу students, пароль нужно менять каждые 3 месяца.

Проверим наличие UID и наличие группы students
```
getent passwd 1234
```

Проверим наличие группы students
```
getent group students
```

Создадим группу students
```
sudo groupadd students
```

Создадим пользователя
```
sudo useradd -u 1234 -m -G students -s /bin/bash user1
```
Описание параметров
`-u 1234` - задать UID пользователя 1234
`-m` - создать домашний каталог пользователя
`-G students` - добавить дополнительную группу пользователю user1 (основной группой будет являться user1, которая создается автоматически)

Зададим пароль пользователю
```
sudo passwd user1
```

Установим максимальный срок действия пароля
```
sudo chage -M 90 user1
```
 
**Проверка:**
```
id user1
getent passwd user1
sudo chage -l user1
stat /home/user1
```

## Раздел 2. Мониторинг файлов и процессов
### 2.1 Мониторинг файлов

**Задание:** Найти в системе все файлы с установленным битом set-UID
 
```
sudo find / -type f -perm -4000 -ls 2>/dev/null > ~/suid_files.out
```
 
 Описание параметров
 `find / -type f` - поиск всех файлов (не каталоги/ссылки/устройства) начиная с корня файловой системы (/)
`-perm -4000` выбирает файлы, у которых установлен бит set-UID
`2>/dev/null` - подавить вывод ошибок в консоль (например Permission denied)

### 2.2 Мониторинг процессов

**Задание:** Найти в системе все процессы, у которых эффективный UID равен 0, а реальный UID относится к обычным пользователям.
 
Обычные пользователи имеют UID > 1000
 
```
ps -eo euid,ruid,pid,ppid,euser,ruser,args | awk 'NR==1 || ($1==0 && $2>=1000 && $2<65534)' | tee ~/proc_monitor.out
```
 Описание параметров
 `ps -e` - вывод списка процессов всех пользователей
`-o euid,ruid,pid,ppid,euser,ruser,args` - задать формат вывода (список интересующих полей для вывода)

Так как в обычном состоянии таких процессов нет, использовался сценарий из задания:

Для демонстрации работы, в другом терминале была запущена сессия пользователя user1 командой su - user1, запущена команда passwd, ввод остановлен на запросе пароля

В выводе виден процесс /usr/bin/passwd с EUID=0 и RUID=1234. Это результат работы механизма set-UID: файл passwd принадлежит root и имеет бит set-UID, поэтому процесс обычного пользователя получает эффективные права root.

## Раздел 3. Механизм set-UID 

**Задание:** Выбрать существующую утилиту (команду BASH). Придумать операцию, которая для своего выполнения требует права root. Например, чтение файла /etc/passwd командой cat.

**Выбранная утилита:** cat.
**Привилегированная операция:** чтение /etc/shadow (файл доступен для чтения только root).
 
Пример из задания (/etc/passwd) не подходит для демонстрации, так как этот файл читается всеми пользователями. Поэтому выбран /etc/shadow.

Для начала убедимся, что для выполнения команды требуются привилегии и выполним её
```
cat /etc/shadow
```

Результатом выполнения будет сообщение **cat: /etc/shadow: Отказано в доступе**

Копируем утилиту cat в домашний каталог пользователя и устанавливаем необходимые права
```
sudo cp /usr/bin/cat /home/user1/mycat
sudo chown root:root /home/user1/mycat
sudo chmod u+s /home/user1/mycat
ls -l /home/user1/mycat      
```
 
Проверка от имени user1:
```
cat /etc/shadow              
./mycat /etc/shadow          
```

## Раздел 4. Механизм привилегий (capabilities)

**Задание:** Выбрать существующую утилиту (команду BASH). Придумать операцию, которая для своего выполнения требует права root. Например, изменение владельца файла на произвольного пользователя командой chown.

**Выбранная утилита:** chown.
**Привилегированная операция:** смена владельца файла на произвольного пользователя (требуется CAP_CHOWN).
```
sudo cp /usr/bin/chown /home/user1/mychown
sudo chown root:root /home/user1/mychown
sudo chmod 755 /home/user1/mychown
sudo setcap cap_chown+ep /home/user1/mychown
getcap /home/user1/mychown 
```
 
**Проверка от имени user1:**
 
```
touch ~/testfile
chown root:root ~/testfile
./mychown root:root ~/testfile
ls -l ~/testfile
```

## Раздел 5. Механизм sudo
 
**Задание:** С помощью механизма sudo разрешить пользователю user1 устанавливать (изменять) системное время.
 
Правило добавлено командой sudo visudo в /etc/sudoers:
 
```
user1 ALL=(root) /usr/bin/date, /usr/bin/timedatectl, /usr/sbin/hwclock
```
 
**Проверка:**
 
```bash
sudo visudo -c
sudo -l -U user1
su - user1
sudo date -s "2026-10-08 12:00:00"
sudo timedatectl set-time "2026-10-08 12:00:00"
```
